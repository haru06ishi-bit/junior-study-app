## 4. 成果の測り方（v0.47.0 から端末内で記録を開始）

- `studyHistory[].answerResults[].assist`（free / hint / choice / none）と `recallMode` を記録している。これで次の数字が端末内で出せる。
  - **選択なら正解だが自力では不正解の割合**
  - **ヒントなしで解けた割合**
  - **日を空けて再現できた割合**（`recallRecords.stage`）
- データは端末の外に送っていない。集計を外部に送るのは、オーナーの承認と個人情報の検討を終えてからにする。
- 学校の成績変化は、提供された場合にだけ扱う。正答率が上がっても「成績が上がった」とは書かない。

## 5. 高校生版（提案のみ・未着手）

- **推奨構成**：エンジンは中学版と共有し、サイトは別にする。同じリポジトリでデータを分け、Cloudflare Pages の別プロジェクトにする（例：hs.サブドメイン）。現在のコードは学年を 1〜3 の数字で持っているため、同じサイトに混ぜると中1と高1が衝突する。
- **最初の対象**：高1英文法・語彙。教科書が違っても内容がほぼ共通で、今の問題形式がそのまま使える。次に数学I/A（数値入力・選択式に限る）、情報I。
- **過去問**：載せない（再利用の条件が未確認）。共通テストの形式に寄せたオリジナル問題に限る。
- **段階的な進め方**
  1. 調査（2〜3週）
  2. 確認済みの約100問で試験版を作る
  3. 8週間、利用状況を測る
  4. 続けるか見直すかを判断する
- **続ける目安（提案値）**：7日後に戻ってくる率20%以上、誤答報告率1%未満、中学版の保守が止まらないこと。
- **リスク**：生成AIで問題を作らせるという強力な代替がある。高校の学外学習率は低い。確認工数は中学の1.5〜2倍と推定。

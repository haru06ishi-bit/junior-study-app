## 5. v0.47.0 の内容（Draft PR の本文に使う）
社会・理科の小テストに「思い出す練習」を追加した。

**流れ**
1. 自分で書いて答える。
2. 間違えたら、ヒント1（文字数）、ヒント2（最初の文字。2文字以下の答えと英数字の答えには出さない）の順に出す。
3. それでも分からなければ選択肢を出す。
4. 正解と解説を表示する。
5. 約4問後に、ヒントなしで再挑戦させる。
6. その後は間隔を空けて復習させる（1・3・7・14・30日）。

**記録**
- `studyHistory[].answerResults[]` に、`assist`（free/hint/choice/none）、`recallMode`、`selfJudged` を追加した。
- 再挑戦の結果は `retryResults` に分けて記録し、得点と問題数には含めない。
- 新しいキー：
  - `recallRecords`：間隔反復の段階。日を空けて自力で2回正解したら「苦手」から外す。3回で「定着」とみなす。
  - `recallPracticePrefs`：教科ごとのオン／オフ（社会はオン、理科はオフが初期値）。
  - どちらもバックアップに含め、統合に対応した。
- 選択肢が見えている状態での正解は、自力の記録にしない（独立監査の指摘1）。

**採点**
- 書き方の違いは、生徒が自分で判定できる。自己判定した正解は自力の正解として数えない。
- 次の表記の違いは、正解として受け付ける：
  - 数字の後の単位（60度 → 60）
  - 47都道府県名の 県・府・都
  - 2文字以上の名前に付く 天皇・時代
  - 「AとB」の順序違い
- 次の問題は思い出す練習の対象から外した：
  - 文や句で答える問題
  - 監査で確認した、正解が一つに決まらない4問（`NON_UNIQUE_IDS`）

**対象数**：社会164問、理科90問。

## 6. Codex の機能の活用方針
次の機能が利用できるか確認し、使えるものは使うこと。費用が発生するもの、外部に接続するものは、オーナーの承認を得てから使う。

- **AGENTS.md**：リポジトリのルールとして自動で読まれる。ルールを変えたら CLAUDE.md と同時に更新する。
- **Codex クラウドのタスクの並列実行**：独立した作業を別々のタスクとして同時に進める。例：
  - 英語の別解の修正
  - 国語の難易度
  - 定期テストの入口
  - 品質・安全
  - 1タスクを1ブランチ・1 Draft PR にまとめる。
- **環境設定**：
  - セットアップスクリプトに `pip` は不要。`npm i --no-save playwright && npx playwright install --with-deps chromium` を入れる。
  - 本番を確認するときだけ、インターネットアクセスで `study.mytools-lab.com` を許可する。
- **GitHub 連携**：Draft PR を作成する。PR に `@codex review` を付けてコードレビューを受ける。これを、実装担当とは別の独立監査として扱う。
- **独立監査の分離**：実装したタスクとは別のタスク（またはレビュー機能）で、コード・問題データ・実際の画面・テスト結果を直接確かめる。実装側の自己評価をうのみにしない。
- **Codex CLI**（手元で使う場合）：既定のサンドボックスと承認モードで作業する。main への push とデプロイは承認なしに実行しない。
- **MCP**：使える場合は Playwright の MCP などで画面を確認する。有料のサービスにつなぐ場合は承認を得る。
- **定期・自動実行**：Codex に定期実行の手段があっても、導入はオーナーの承認後にする。導入する場合の範囲は、CI の確認 → 課題の優先順位付け → 実装 → テスト → 監査 → Draft PR → 報告まで。自動マージ・自動公開はしない。
